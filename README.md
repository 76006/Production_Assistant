# 生产助手

基于 Qt Widgets 和 Qt SerialPort 的下位机生产配置工具。

## 功能

- 自动枚举串口，也可手动输入串口名称；支持包括 `460800` 在内的常用波特率
- 六项操作按“左侧操作、右侧独立状态”排列，并提供生产流程一键配置
- 密码不会以明文写入收发日志或配置文件
- 每个操作分别显示等待、进行中、成功或失败
- 支持设备明确拒绝、串口异常和 3 秒响应超时
- 收发记录便于现场排查
- 顶部“清空所有状态”可将生产配置、4G 配置和链路测试结果恢复为等待状态
- 独立的“4G 路由器配置与检测”标签页，支持单项检测和一键顺序配置
- 内置最小 MQTT 3.1.1 客户端，可配置 Broker、订阅、发布并与串口双向测试
- 支持将常用输入内容保存到程序目录下的 `ProductionAssistant.ini`

## 默认串口协议

UID 指令以单个 `\r` 结尾，其他命令以 `\r\n` 结尾：

| 操作 | 默认发送格式 |
| --- | --- |
| 输入密码 | 发送密码框内的内容；首次启动为空，需手动输入 `mei+688` |
| 配置初始时间 | 发送输入框内的完整指令，初始值为 `date 2025 10 30 0 0 0` |
| 读取 UID 设置状态 | `set_board_UID`；收到非空的有效状态文本即显示成功 |
| 修改 UID | 输入内容不增加命令头；清除隐藏换行后追加单个 `\r`（十六进制 `0D`）触发 MSH 执行；日志显示实际字节数和末尾十六进制字节 |
| 配置当前时间 | `date 年 月 日 时 分 秒`，例如 `date 2026 9 9 11 20 30` |
| 重启 | `reboot` |

密码操作收到 `command not found.` 或 `msh />` 时判定验证成功。密码框只在发送 `mei+688` 并验证成功后记录“曾成功配置”的布尔标记，之后启动软件才会自动填入 `mei+688`；不会保存密码原文。

读取 UID 设置状态时，如果设备返回 `command not found.`，操作失败并提示“命令不存在，请将版本升级为测试版本”。UID 修改操作收到包含 `ok` 的回复（忽略大小写）时判定成功，没有返回时在 3 秒后判定失败。其他配置操作返回以 `OK`、`ACK`、`SUCCESS`、`PASS` 或“成功”开头时判定成功；以 `ERR`、`ERROR`、`FAIL`、`FAILED`、`NACK`、`NG` 或“失败”开头时判定失败。协议如有不同，请集中修改 `src/serialprotocol.cpp`。

配置初始时间和当前时间采用错误排除规则：如果返回 `please input: date [year month day hour min sec] or date`、`command not found.` 或其他明确失败回复，则提示“请检查命令格式是否错误”；等待 3 秒没有收到这些错误信息也判定设置成功。

重启指令成功写入串口后立即显示“已发送重启”，不等待也不识别设备重启回复。

生产配置页的“一键配置并重启”要求密码、初始时间和 UID 三个输入框都有内容。完整流程共 6 步：密码、初始时间、读取 UID 设置状态、发送 UID、当前时间、重启；每一步确认成功后等待 2 秒再执行下一步，失败或超时会立即停止。

顶部“保存配置”按钮会保存初始时间指令、4G 配置的四个参数，以及 MQTT 的 Broker 地址、端口、Client ID、订阅主题和发布主题。上述输入框每次修改时也会自动保存，下次启动自动恢复。配置文件名为 `ProductionAssistant.ini`，与正在运行的 `ProductionAssistant.exe` 位于同一目录；密码和 UID 不写入该文件。

## 4G 路由器配置与检测

页面将“发送按钮、参数信息、执行状态”分为三列。输入框只填写等号后的参数，程序会自动与对应命令头组合；四条 AT 指令均以 `\r\n` 结束。默认组合结果为：

1. `AT*GPSCFG=4,5,0`
2. `AT*SERVER0=9,broker.emqx.io,1883`
3. `AT*MQSET0=00000001,,`
4. `AT*MQTOP0=sendev/1/temperature,sendev/10/temperature`

每个参数框都可以修改，例如服务器参数修改后会形成 `AT*SERVER0=<当前输入内容>`。参数为空时不会发送。每条指令只有收到完全大写的独立回复 `OK` 才判定成功。“一键配置”要求四个参数框都有内容，先发送第 1 条，收到大写 `OK` 后等待 2 秒才发送下一条；最后一条也收到大写 `OK` 后整体完成。任一步返回错误或 5 秒内没有收到大写 `OK`，流程立即停止并显示失败步骤。

完成配置后需要重启 4G 路由器，使 MQTT 参数生效并重新连接 Broker。

## MQTT 收发

“MQTT 收发”标签页提供最小化的 MQTTX 类似功能：

- 配置 Broker 地址、端口、Client ID，以及可选的用户名和密码
- MQTT 3.1.1 普通 TCP 连接，当前支持 QoS 0 发布和订阅
- 连接成功后自动订阅输入框中的主题，也可以手动重新订阅
- 将消息发布到指定 MQTT 主题
- 将同一消息原样通过串口发送，可选不加结尾、添加 `CRLF` 或添加 `LF`
- 双向消息记录同时显示 MQTT 收发和串口收发
- 一键双向连接测试，可设置 5–600 秒的持续时间
- Broker、端口、Client ID、用户名、主题和串口结尾设置自动保存；密码不会保存

`AT*MQTOP0` 的两个参数顺序是“路由器订阅主题, 路由器发布主题”。根据当前配置，电脑端默认主题为：

- 电脑发布到 `sendev/1/temperature`，用于向路由器下发数据
- 电脑订阅 `sendev/10/temperature`，用于接收路由器向 MQTT 发布的数据

当前最小版本不包含 TLS/证书、WebSocket、QoS 1/2、保留消息开关和遗嘱消息。

### 一键连接测试

开始测试前需要同时连接串口和 MQTT。程序会在设置的时间内循环执行：

1. 发送 `PA_TEST_S2M_<会话编号>_<轮次>` 到串口，只有从 MQTT 订阅主题收到相同测试标识才判定上行成功。
2. 发布 `PA_TEST_M2S_<会话编号>_<轮次>` 到 MQTT，只有从串口收到相同测试标识才判定下行成功。
3. 任一方向 3 秒内没有完成闭环，立即停止并显示失败方向；达到测试时长且两个方向至少各成功一次，显示双向正常及成功次数。

串口接收采用 50ms 静默组帧，解决一次消息被 `QSerialPort::readyRead` 分多次交付而显示成多段的问题。若实际设备发送一帧时的字节间隔超过 50ms，应改用协议长度字段或明确结束符进行可靠组帧。

## 构建

需要 Qt 5/6 的 Widgets、SerialPort 组件和 CMake：

```powershell
cmake -S . -B build -DCMAKE_PREFIX_PATH="D:/Qt/6.5.3/mingw_64"
cmake --build build
```

也可以直接用 Qt Creator 打开根目录的 `CMakeLists.txt`，选择带有 SerialPort 组件的 Qt 套件后构建运行。
